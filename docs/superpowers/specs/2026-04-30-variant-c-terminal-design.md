# Variant-C "Terminal" Dashboard Redesign

**Status:** Draft
**Date:** 2026-04-30
**Branch:** `feat/variant-c-terminal`
**Source design:** `docs/design_handoff_claude_stats_terminal/` (component specs, design tokens, layout grid — referenced throughout this spec; the handoff README is the source of truth for component-level details like spacing, type sizes, and stroke widths)

## Goal

Migrate the Claude Stats dashboard from its current multi-color "AI dashboard" look to the **Variant-C "Terminal"** design: structured, calm, information-dense, monospace-forward, single-accent terracotta, light + dark mode.

## Non-goals

- No stack migration. The dashboard stays as a self-contained HTML file generated by `extract_stats.py`.
- No feature removal. Every feature in the current dashboard is preserved.
- No architectural rewrite of `extract_stats.py` beyond extracting templates from inline strings.

## User-confirmed decisions

| # | Topic | Decision |
|---|---|---|
| 1 | Scope | Main dashboard **+ project + session detail pages** in a single branch |
| 2 | Implementation strategy | **Extract templates** from `_get_html_template()` first (Phase 0), **then** redesign tab-by-tab |
| 3 | Range filter values | **Keep current** values: `All / 7D / 30D / 90D / 1Y` (only optic changes) |
| 4 | Quick filter placement | Inline in primary-nav row, **directly left of the range buttons** |
| 5 | Charts | **Hybrid**: Chart.js (re-styled) for complex charts + custom CSS/HTML for heatmap, distribution bars, hourly histogram |
| 6 | Theme | **System pref + explicit toggle**, override stored in localStorage |
| 7 | Localization | **Pragmatic bilingual**: KPI labels and section headers stay English (Terminal-style code tokens), tab names + tooltips + body text are localized de/en |
| 8 | Feature preservation | All existing features kept; specific items below |

### Specific feature decisions

- **F2 Anonymization**: hotkey-only as today (no UI toggle button). Toast notification gets Terminal-look. Project names continue to use deterministic `anonName()` replacement.
- **Anonymization for unpredictable text**: CSS blur (`filter: blur(4px)`) for plan-mode plan titles, session first-prompts, memories, skills/hooks descriptions. Replaces the current "hide entirely" behavior for first-prompt.
- **Language toggle**: new UI toggle in top-bar (in addition to current `config.json` language setting).
- **Billing cycles**: Current cycle progress bar (per mockup) **plus** list of all historical cycles below.
- **Insights tab**: extended beyond mockup with Storage, Telemetry, Performance sections (existing features that aren't in the mockup).

## Architecture

### Phase 0 — Template extraction (refactor, no UI change)

Move inline HTML/CSS/JS strings out of `extract_stats.py` into separate template files. Output of `extract_stats.py` must remain byte-equivalent.

**Target structure:**

```
templates/
├── dashboard.html          (markup with placeholders)
├── dashboard.css           (styles)
├── dashboard.js            (renderers + logic)
├── project_detail.html
├── project_detail.css
├── project_detail.js
├── session_detail.html
├── session_detail.css
└── session_detail.js
```

**Build pipeline in `extract_stats.py`:**
1. Read the three template files via `Path.read_text()`.
2. In `dashboard.html`, replace marker `<!-- STYLES -->` with `<style>{css}</style>` and `<!-- SCRIPTS -->` with `<script>{js}</script>`.
3. Apply existing locale/version/data placeholder replacement.
4. Final output remains 1:1 self-contained (templates are internal-only build inputs).

**Placeholders preserved as-is:** `__L_*__`, `__VERSION__`, `__DATA_PLACEHOLDER__`, `/*__DASHBOARD_DATA__*/`.

**Verification:**
1. Before Phase 0: run `extract_stats.py`, save output as `index.html.before`.
2. After Phase 0: run again, save as `index.html.after`.
3. `diff -w index.html.before index.html.after` must be empty.
4. Repeat for at least 3 sample project + session detail pages.
5. Browser smoke test: all tabs, range filter, F2 anonymization, session replay.

**Subagent handling:** Phase 0 is done **inline, not subagent-driven**. The diff verification sits too close to the output for delegation; risk of "incidental refactoring" is too high.

### Phase 1 — Persistent shell + design tokens

Introduce Variant-C CSS variables (light + dark) and rebuild the persistent shell components. Old tab content remains functional inside a temporary legacy wrapper, replaced incrementally in Phase 2.

**Components rebuilt:**

| Region | Components |
|---|---|
| Top bar | Brand mark + `CLAUDE.STATS` + version, USER/PLAN/RANGE label-value pairs, language toggle (`DE`/`EN` text button), theme toggle (`☼`/`☾` glyph button), `F2: ANON` hint label in `--fg-3`, UTC time |
| Primary nav | Tabs (Cost, Activity, Projects, Sessions, Plan, Insights, Agents) with terracotta underline on active. Right side: quick-filter input + range segmented control |
| KPI strip | 5 cells: API Equivalent (primary, terracotta), Sessions, Messages, Output Tokens, Cache Hit |

**Theme behavior:**
- Default: respects `prefers-color-scheme: dark`.
- Explicit toggle stores choice in `localStorage`.
- Toggle triggers re-evaluation of Chart.js defaults from CSS variables and re-renders charts.

## Data flow

The mockup's `data.js` is a schema reference only. Real data comes from `dashboard_data.json` as today.

**Direct mapping (existing fields):**

| Variant-C field | Source |
|---|---|
| `kpi.api_equivalent` | existing `total_cost` |
| `kpi.actual_paid` | derived from `plan_history` for active range |
| `kpi.sessions`, `kpi.messages` | existing counts |
| `kpi.output_tokens`, `kpi.input_tokens` | existing token sums |
| `kpi.cache_read`, `kpi.cache_write` | existing cache tokens |
| `daily_cost[]` | existing `daily_costs` |
| `models[]`, `projects[]`, `hourly[24]`, `weekday[7]` | existing |
| `recent_sessions`, `top_tools` | existing |

**Computed client-side in `dashboard.js`:**

| Field | Computation |
|---|---|
| Cache-Hit % | `cache_read / (cache_read + input_tokens)` (verify against existing if present) |
| API save % | `(api_equivalent - actual_paid) / api_equivalent * 100` |
| Avg session duration | sum of session durations / session count |
| Messages per session | total messages / session count |
| Heatmap matrix `[7][18]` | aggregation from `daily_costs` (7 weekdays × 18 weeks) |
| 7-day moving average | rolling window over `daily_cost[]` |

Computing client-side avoids changes to the Python data pipeline.

## Chart.js theming

Single `setupChartDefaults()` function in `dashboard.js`, called on init and on theme change:

```js
Chart.defaults.font.family = "Geist Mono, ui-monospace, monospace";
Chart.defaults.font.size = 11;
Chart.defaults.color = getCSSVar('--fg-3');
Chart.defaults.borderColor = getCSSVar('--grid');
Chart.defaults.scale.grid.color = getCSSVar('--grid-2');
Chart.defaults.scale.grid.borderDash = [1, 3];
Chart.defaults.scale.ticks.color = getCSSVar('--fg-3');
Chart.defaults.elements.line.borderWidth = 1.5;
Chart.defaults.elements.line.borderColor = getCSSVar('--accent');
Chart.defaults.elements.point.radius = 0;
Chart.defaults.plugins.legend.display = false;
Chart.defaults.plugins.tooltip.backgroundColor = getCSSVar('--panel');
Chart.defaults.plugins.tooltip.borderColor = getCSSVar('--grid');
Chart.defaults.plugins.tooltip.borderWidth = 1;
Chart.defaults.plugins.tooltip.cornerRadius = 0;
```

**Custom CSS components (no Chart.js):**
- Heatmap (CSS grid, 7×18 cells, `aspect-ratio: 1`, opacity gradient `0.08 + intensity * 0.92`)
- Hourly histogram (24-bar CSS grid, height = `value/max * 100%`)
- Distribution bars (used for models, weekday, top-tools, plan-comparison)

**Cost-chart moving average ghost line:** stays in Chart.js as a second dataset with `borderDash: [4, 2]`, opacity 0.6, color `--fg-2`.

## Anonymization

**Deterministic replace** (project names) — kept as-is.

**CSS blur** for unpredictable text in `body.anon-mode`:
- Plan-mode plan titles (Insights tab)
- Session first-prompts (replaces current "hide entirely")
- Memories on project detail pages
- Skills / hooks descriptions
- Any future text where the value can't be deterministically anonymized

**Implementation:** wrap target text in `<span class="anon-blur">`, with CSS:
```css
body.anon-mode .anon-blur { filter: blur(4px); user-select: none; }
```

**Toast notification** (Variant-C look): 1px-border in `--accent`, monospace, no border-radius.

## Localization (de/en)

**Stay English (treated as code tokens, not translated):**
- KPI labels: `API EQUIVALENT`, `SESSIONS`, `MESSAGES`, `OUTPUT TOKENS`, `CACHE HIT`
- Section header glyphs: `↳ Token & API Value`, `↳ Activity`, etc.
- Range buttons: `7D / 30D / 90D / 1Y / All`
- Stat row keys for technical metrics where German is awkward (e.g. `cache.efficiency`, `output_tokens`)

**Localized to de/en** via existing `__L_*__` pattern:
- Tab names (`Cost` → `Kosten`)
- Tooltips
- Body text and prose
- Button labels (`Download`, `Anonymize`, etc.)
- Stat row keys where German is natural (e.g. `peak hour` → `Spitzenstunde`)

New `__L_*__` placeholders are added to both `locales/en.json` and `locales/de.json`.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Phase 0 produces output diff despite pure extraction | Medium | Diff verification as hard gate; rollback on failure |
| Chart.js theme override doesn't apply on theme toggle | Medium | Theme toggle calls `chart.update('reset')` on all instances; CSS vars re-read |
| Session-flow particles look dull after single-accent reduction | Low | Keep opacity + pulse animation variation; separate retuning task if visually flat |
| Heatmap data not aggregated server-side | Low | Aggregate client-side from `daily_costs` (no Python change) |
| Mobile layout breaks (1px borders look bad on touch) | Medium | Phase 4 mobile pass; range buttons + filter wrap to own row at <960px |
| DE locale strings sound awkward for new labels | Low | Strategy C (pragmatic bilingual) handles this — Terminal code tokens stay English |
| Phase 2 subagents take refactor liberties and break features | Medium | Hard acceptance criteria per subagent task ("F2 works", "filter works"); main reviews each subagent output before commit |
| Build pipeline (cron) fails after Phase 0 | Low | Local smoke test before Phase 0; cron runs from working dir, branch switches affect live — branch switch with cron awareness |

## Out of scope

- Onboarding / empty states
- Loading states (dashboard is statically generated)
- Error states (same reason)
- Settings / account management
- Mobile-first redesign (only breakpoint adaptation)
- Stack migration to React/framework
